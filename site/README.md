# SIFF 2026 — Fan Showcase

A static, bilingual (EN / 中) showcase of every film and program announced for the **28th Shanghai International Film Festival** (June 12 – 21, 2026).

Fan-made. Not affiliated with the festival.

## Live

Deploy `public/` as the static root. The site is a single self-contained app: HTML + CSS + a generated `data.js` + React via CDN. No build step at request time.

## Layout

```
site/
├── public/              ← deploy this directory as the site root
│   ├── index.html       ← page shell, all CSS
│   ├── app.jsx          ← React app (compiled in-browser by Babel standalone)
│   └── data.js          ← AUTOGENERATED — window.SIFF_DATA = { programs, films }
├── data/
│   ├── siff-com-2026-05-17.csv    ← raw crawl from siff.com
│   ├── programs.json              ← parsed: 16 programs
│   ├── films.json                 ← parsed: 105 films (skeleton fields)
│   └── enrichment.json            ← hand-curated overrides — director, synopsis, poster URL, etc.
└── scripts/
    ├── parse_csv.py     ← CSV → programs.json + films.json
    └── build_data.py    ← programs + films + enrichment → public/data.js
```

## Updating the catalog

### Add a new film to an existing program

Edit `data/films.json` and append an object:

```json
{
  "id": "tribute-ken-loach-some-new-loach-film",
  "title_en": "SOME NEW LOACH FILM",
  "title_zh": "肯·洛奇新片",
  "year": 2026,
  "format_tags": [],
  "program_id": "tribute-ken-loach",
  "program_en": "Tribute · Ken Loach, Master of Realism",
  "program_zh": "向大师致敬 ｜ 写实巨匠肯·洛奇",
  "order_in_program": 8,
  "color": "#5a4a3a"
}
```

Then rebuild: `python3 scripts/build_data.py`

### Add a new program

Edit `data/programs.json` and append a program object (id, title_en, title_zh, kind_en, kind_zh, color, blurb_en, blurb_zh). Add films referencing that `program_id`. Rebuild.

### Auto-enrich all films from TMDB (recommended)

Posters, synopses (EN + 中文), runtimes, directors, IMDb IDs — all of this can
be fetched in one pass from [The Movie Database](https://www.themoviedb.org):

```bash
# 1. Get a free TMDB v3 API key from
#    https://www.themoviedb.org/settings/api
export TMDB_API_KEY="your-key"

# 2. Run the enrichment (idempotent, resumable, ~2 minutes for 105 films)
cd site
python3 scripts/enrich_from_tmdb.py

# 3. Rebuild the bundle and commit
python3 scripts/build_data.py
git add data/enrichment_tmdb.json public/data.js
git commit -m "Enrich films from TMDB"
git push
```

Results land in `data/enrichment_tmdb.json`. `build_data.py` merges them in
this priority: **enrichment.json (hand-curated) > enrichment_tmdb.json (auto)
> CSV skeleton.** So hand-curated edits always win, and rerunning the script
won't trample your work.

Once enrichment has run, every film modal shows a yellow **IMDb** button
linking straight to `imdb.com/title/{id}/`. Films without an IMDb ID (e.g.
TMDB couldn't find them) still get a "Find on IMDb ↗" search link.

### Enrich a single film by hand

Edit `data/enrichment.json`, keyed by the film's `id`:

```json
"tribute-ken-loach-some-new-loach-film": {
  "director": "Ken Loach",
  "director_zh": "肯·洛奇",
  "country": "United Kingdom",
  "country_zh": "英国",
  "runtime": 110,
  "language": "English",
  "synopsis_en": "…",
  "synopsis_zh": "…",
  "poster_url": "https://your-cdn.example/posters/loach-2026.jpg"
}
```

Rebuild: `python3 scripts/build_data.py`. The site will render the supplied poster image inside the poster frame; otherwise it falls back to a typographic placeholder.

### Re-import from a new CSV crawl

Drop the new CSV at `data/<name>.csv`, point `SRC` in `scripts/parse_csv.py` at it, run both scripts.

## Deployment

### Cloudflare Pages (recommended)

1. Push this repo to GitHub.
2. In Cloudflare Pages, create a new project, connect the repo.
3. **Build command:** `python3 scripts/build_data.py`
   - Or skip the build entirely and commit `public/data.js` directly (it's checked in).
4. **Build output directory:** `site/public`
5. Save. Cloudflare deploys on every push to `main`.

`_headers` and `_redirects` files in `public/` are honored by Cloudflare Pages automatically.

### GitHub Pages

Either commit `public/` and point Pages at it (Settings → Pages → branch `main` /  folder `/site/public`), or use the supplied workflow at `.github/workflows/deploy.yml` (runs the Python build and uploads `public/` as a Pages artifact).

### Plain static host (Netlify, S3, etc.)

Upload the contents of `public/` to the root of any static host.

## Notes

- React, ReactDOM, and Babel-standalone load from unpkg via `<script>` tags. No bundler needed.
- All data is embedded in `data.js` — there are no runtime `fetch` calls, so the site works on any static host with no CORS concerns.
- Poster images, when added via `enrichment.json`, should be reasonable in size (e.g. 600×800 JPG/WEBP) and CORS-friendly. The site lazy-loads them.
- The site is fully static and offline-capable once loaded.
